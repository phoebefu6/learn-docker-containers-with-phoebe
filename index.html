Learn Docker & Containers with Phoebe

Why it works on your laptop and nowhere else, and the one container that fixes it. Write a Dockerfile for a data project, keep rebuilds fast, and run the whole stack with one command. One question runs through all six sessions: if your laptop died tonight, could a teammate run your project tomorrow with one command, and how long would the rebuild take? You need a terminal you are comfortable in (Learn the Command Line first if not) and nothing else: every build-along runs in the page.

The six sessions 🎯 · from a list of hidden dependencies to an image you can ship

The running case is Stackyard, a constructed four-person analytics team whose Jupyter notebook, small FastAPI scoring API, nightly Python job and Postgres database all work on exactly one analyst's laptop. Each session adds one piece to Stackyard's container kit, and the last session scores the whole kit.

💻 Session 1 · foundations

Why it works on your laptop and nowhere else

The hidden dependencies a project carries without anyone writing them down: OS libraries, the Python version, environment variables, data paths, the clock. Virtualenv, container and virtual machine, side by side. Build-along: Stackyard's dependency inventory.

▶ Start here 🧱 Session 2 · foundations

Images, containers, layers: the mental model

An image is a read-only stack of filesystem changes; a container is that stack plus one writable layer. Tags against digests, registries, and what an OCI image actually contains. Build-along: read a Dockerfile line by line and predict its layers.

the mental model 📝 Session 3 · core

Writing a Dockerfile for a Python data project

FROM, WORKDIR, COPY, RUN, ENV, EXPOSE, CMD against ENTRYPOINT, .dockerignore, pinning and a non-root USER, each with the reason it exists. Build-along: containerise the Stackyard scoring API.

your first Dockerfile ⚡ Session 4 · bench night

The layer cache lab

Edit a Dockerfile, change one file, and the lab walks Docker's cache rules for real: which layers rebuild, how long, how big the image ends up, and what a hadolint-style lint says. Then break it on purpose and watch the rebuild jump.

★ the bench 🎛️ Session 5 · stretch

Compose: notebook, API, database, one command

Services, the default network and service-name addresses, ports, volumes, depends_on with a healthcheck, and env files. Build-along: compose.yaml for Stackyard's notebook, API and Postgres, plus the nightly job.

one command 🚢 Session 6 · capstone

Smaller, safer, shippable

Multi-stage builds, slim against alpine against distroless (and the honest argument about alpine for Python), image scanning as a category, secrets that never touch a layer, and a release checklist. Capstone: Stackyard's container kit, scored.
